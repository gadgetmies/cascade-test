## 2026-04-18 - [CRITICAL] Prevent Arbitrary Directory Deletion via Coverage Config
**Vulnerability:** Arbitrary directory deletion in the test runner. The `--coverage-dir` option was used directly in `fs.rmSync(..., { recursive: true, force: true })` without any validation. An attacker or accidental user error could result in the deletion of the entire project root or sensitive system directories (e.g., `/`, `/tmp`) if provided as the coverage directory.
**Learning:** Utilities that perform destructive file operations (like recursive deletion) based on user-provided paths must always validate those paths against a safe base directory. `path.join` and `path.resolve` are not enough to prevent traversal or escaping the intended scope.
**Prevention:** Implement strict path validation by resolving the user input and checking it against the expected boundary (usually the current working directory) using `path.relative`. Ensure the relative path does not start with `..`, is not an absolute path (after relativity check), and is not empty (pointing to the root itself).
